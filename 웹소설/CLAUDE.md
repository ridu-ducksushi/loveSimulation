# loveSimulation 웹소설 회차 작성 규칙

> **이 문서는 `웹소설/` 폴더의 회차 작성 SSOT다.**
> Claude 는 웹소설 회차 신규 작성·수정 시 반드시 이 규칙을 먼저 읽고 따른다.
> 규칙 변경이 필요하면 본 문서를 먼저 수정한 뒤 본문 작업으로 넘어간다.

---

## 0. 작품 톤 한 줄 정리

회빙환 + 가해자(아델린) 빙의 + 다공략 + **자조·서늘함·미스터리** 톤의 정통 로판.
"이번엔 내가 가진다" 류 직설 결의·자아도취 멋 부림 절대 금지.
정체·정보 직설보다 *행동·시선·암시* 우선.

---

## 1. 새 회차 작성 전 필수 Read 순서

회차 작성 전 아래 자료를 **반드시** 순서대로 읽고 시작한다 (자동 로드 의존 금지).

1. `웹소설/CLAUDE.md` *(= 본 문서, 규칙 재확인)*
2. `웹소설/작품소개.md` — 작품 톤·후크·미스터리 SSOT
3. `loveSimulation/Assets/Resources/Dialogues/chapter_summary.md` — 게임 전체 챕터별 사건·흐름
4. `loveSimulation/Assets/Resources/Dialogues/character_settings.md` — 캐릭터 voice·호칭·외형 SSOT
5. `웹소설/회차요약.md` — 기존 웹소설 회차 한 줄 요약 *(없으면 신규 생성)*
6. **직전 1~2개 회차 마크다운 본문** — 톤·문장 호흡·끝맺음 흐름 직접 확인
7. (선택) 매핑되는 게임 챕터 JSON — `loveSimulation/Assets/Resources/Dialogues/chapter{N}.json`

## 2. 분량 규칙

- **본문 최소 4000자 (하한 의무)** *(2026-04-28 사용자 결정)*
  - 권장: 4000~6000자 (한국 웹소설 1화 표준 분량)
  - 게임 챕터 풍성도가 큰 회차는 6000~10000자도 허용 (§9 "내용·후크 우선, 분량 가변" 정책)
  - **4000자 미만 금지** — 짧은 호흡은 한국 웹소설 독자 이탈 1순위
- **카운트 기준**: 한국어 본문(공백 포함). 마크다운 헤딩(`#`), 구분선(`---`), 끝맺음 멘트(`*— N+1화에서 계속*`), 인용블록(`>`) 등 부가 표기는 제외
- **검증 가이드**: 전체 파일 `wc -m` 결과가 본문 글자수의 근사치 (마크다운 부가량 약 300~500자 고려). `wc -m ≥ 4500` 정도면 본문 4000자 하한 안전.
- 분량을 채우기 위한 늘어진 묘사·말 늘이기 금지 — 호흡이 길어지면 그 자체로 독자 이탈
- 분량 부족 시: 묘사 추가가 아니라 *장면 한 컷 추가*(시선의 교차·작은 접촉·내적 독백 한 단락)로 채움

---

## 3. 마크다운 구조 규칙

- **첫 줄**: `# {N}화. {한글 부제}` (예: `# 1화. 공작가의 불청객`)
- **단락**: 1~3문장으로 짧게 끊고 빈 줄로 분리 (모바일 가독성)
- **장면 전환**: `---` (수평선) — 한 회차당 2~4개
- **강조 표기**:
  - 내적 독백·외부 인용 강조: `*기울임*`
  - 핵심 단어·반전 단어: `**굵게**` — **한 회차 3회 이내** (남발 시 효과 죽음)
- **끝줄**: `*— {N+1}화에서 계속*`

---

## 4. 시점 / 화자 규칙

- **기본 시점**: 1인칭 (주인공 = 전생 대공비 / 회귀 후 에밀리아)
- 한 회차 안에서 시점 흔들림 금지
- 전생 ↔ 현재 시점 전환은 반드시 `---` 구분선 + 시점 명시 (날짜·계절·장소 디테일)
- 다른 캐릭터 시점이 필요하면 별도 외전 회차로 분리

---

## 5. 캐릭터 voice 규칙

`character_settings.md` "말투" 섹션을 **절대 준수**. 아래는 핵심 요약 (변경 시 SSOT 먼저 수정).

| 캐릭터 | voice |
|---|---|
| **공작** | 평소 "~하시오", "그대" 격식체 / 가면이 무너질 땐 짧은 명령조·말끝 흐림·낮은 톤 |
| **에르하** | 들뜬 반말 + 항상 `"주인"` 호칭 / `"야"`·`"너"` 거친 호칭 절대 금지 / 흔들림은 어미·호흡·송곳니 묘사로 |
| **카이델** | 철저한 존댓말 "~하십시오", "~입니다" / 흔들리면 경어가 어색하게 일그러지며 낮고 탁한 음성 |
| **렌** | 반·존댓말 자유, `"어이~ 우리 아가씨"`, `"고객님~"` 능청 / 진심 새어 나올 땐 미소는 그대로 톤만 한 단계 낮아짐 |
| **기사단장** | 단답형 "예, 각하" / 화 극에 달했을 땐 더 낮게 깔리는 저음 |
| **백작** | 냉정·계산적, 도구로 다루는 듯한 어조 |
| **주인공 1인칭** | 단정·서늘. 속마음(나레이션)은 직설적·자조적 / 타인 앞에선 아델린 가면(여리고 조곤조곤) |

## 6. 호칭 SSOT

- 캐릭터별 호칭은 `character_settings.md` 정의 외 임의 변경 금지
- 새 호칭 도입 시 `character_settings.md` 를 **먼저** 갱신 후 본문 작성
- 호칭 한 단어가 캐릭터 voice 의 절반을 결정 — "주인" → "너" 한 번 바뀌는 순간 결이 통째로 무너짐

---

## 7. 끝맺음 (Cliffhanger) 규칙

한국 웹소설은 *매 회* 다음 회를 클릭하게 만드는 한 컷으로 닫혀야 한다. 다음 중 **1개 이상** 필수:

- **정보 반전**: 새 사실·배신·정체 노출
- **미스터리 추가**: 새 떡밥 / 풀리지 않은 의문
- **위기**: 전투 직전·스킨쉽 직전·습격 직전
- **첫 등장**: 새 캐릭터·새 장소·새 아이템의 등장
- **결단의 한 컷**: 주인공의 차가운 *행동* 한 줄 (단, 자아도취 결의문 금지 — 행동·표정으로만)

## 8. 톤·연출 규칙

- **야릇 결은 회차 전반에 흩뿌릴 것** *(2026-04-28 3화 사용자 피드백 — "한 컷"으로 끝나지 말 것)*
  - **패턴: 미세 야릇 2~3 + 절정 야릇 1단락**
  - **미세 야릇** (회차 곳곳): 시선 한 박자, 무릎이 닿을 뻔하고 거두는 한 뼘, 호흡이 미세하게 어긋남, 손등 위 시선의 무게, 입술이 닿을 듯 멈춤. 절제 속 흔들림.
  - **절정 야릇** (회차당 1단락만, 길게): 닿을 듯 닿지 않는 입술이 살갗 가까이 멈춤, 호흡이 손가락 끝에 잘게 끊겨 닿음, 검에 닳은 손바닥이 손등 위에 덧대짐 등 농밀한 한 단락
  - **핵심 = 절제와 농밀의 낙차**. 평소엔 절제, 한 곳에 폭발. 매 단락마다 야릇이면 효과 죽음.
  - 캐릭터별 *시그니처 결* *(2026-04-28 사용자 피드백 — 손/팔 편중 회피)*:
    - **카이델** = 머리카락·뒷목·턱(분석 학자 결, 닿을 듯 닿지 않음). *손목/손바닥은 게임 본문 정사 컷에만 한정 사용*
    - **렌** = 입술·쇄골·귀/입김·턱(능청 도발) — 손은 *살짝 스치는 보조*에만
    - **에르하** = 허리·귀·송곳니·등 뒤·허벅지(포식자, 메모리 #3)
    - **기사단장** = 어깨·뺨·뒷목·등(절제 깨짐) — 손등 정맥은 게임 last_touch 정사에만
    - **대공** = 시선의 무게·목덜미·쇄골 언저리(직접 접촉 절제, 전생 톤 보존)
  - **정량 가이드** *(2026-04-28 4화 검수 후 사용자 피드백)*:
    - 한 회차 야릇 컷의 **손/팔 계열 비율 ≤ 40%**. 손목·손바닥·손가락·손등·팔목·팔뚝은 모두 *손/팔 계열*로 카운트.
    - 비-손/팔 부위로 분산 의무: **허리·머리카락·얼굴·입술·귓볼·목덜미·쇄골·뒷목·턱·뺨·등 뒤·허벅지·시선·호흡** 적극 활용.
    - 작성 직후 자가 점검 — 회차 야릇 컷 부위를 카운트해 분포 검증.
  - **회차 간 누적 다양화**: 같은 캐릭터의 같은 부위는 회차 간 *최소 2회차 간격* 두고 재사용. `회차요약.md` 의 *부위 사용 기록* 참조.
  - `character_settings.md` 외형/관능 묘사 적극 활용. **체온·숨결·살갗·시선의 온도** 같은 감각 묘사 우선.
- **자조·서늘함 우선**: 1인칭 독백은 항상 자조 톤
  - 좋은 예: *"이 사람은 한 번도 나를 사랑한 적이 없었다."*
  - 나쁜 예: *"이번엔 내가 가진다."* / *"두 번 다시 가만히 죽지 않는다."*
- **직설적 결의·도발 금지** — 자아도취 멋 부림은 한국 로판 독자 1순위 비호감
- **미스터리 우선**: 정체 직설 < 행동 암시. 독자 머릿속에 그림이 그려져야 후크가 산다
  - 좋은 예: *"누구도 길들이지 못한 짐승이 곁에 누워 잠들었다."*
  - 나쁜 예: *"천년 묵은 용 에르하가 곁에 있었다."*
- **묘사의 비대칭**: 핵심 한 컷은 길게·관능적으로 / 그 외는 짧고 차갑게
- **em dash(—) 절제** *(메모리 `feedback_em_dash_restraint.md`)*: 한 회차당 **3~5개 상한**. 기본 default = 안 쓴다. 사용은 ① 말이 진짜로 끊긴 순간 ② 생각이 단절되는 내면 독백 ③ 액션 직전의 진짜 서스펜스에만. 강조·부연·줄바꿈 직후 첫 단어·끝맺음 회피용 금지. 작성 직후 `grep -o "—" 파일 | wc -l` 카운트.
- **스킨쉽 부위 다양화** *(메모리 `feedback_scenario_tone.md` #2)*: 같은 캐릭터 연속 씬·회차에서 동일 부위 반복 금지. 대안 — 허리 뒤·어깨·턱·뒷목·쇄골·머리카락·뺨·귀/입김·등 뒤·허벅지. 게임 본문 기준 이미 사용 — 카이델 = 손목·손바닥·머리카락 / 렌 = 미세 도발 / 에르하 = 허리·귀·송곳니. **수위 있는 로맨스**: 단순 플라토닉 X. 체온·숨결·살갗·시선의 온도 같은 감각 묘사 적극.
- **에밀리아 자발성 프레임 금지** *(메모리 `feedback_scenario_tone.md` #5)*: 원몸 주인(에밀리아)의 과거 행동(공작 유혹·노예 경매 연루 등)을 회상·평가할 때 반드시 *백작의 지시·세뇌 결과*로 처리. "외로워서", "사랑받고 싶어서", "본인 욕망으로" 같은 자발성 프레임 금지. 회귀 후 회차(3화~)에서 특히 주의.

## 9. 게임 챕터 ↔ 웹소설 회차 매핑

### 가속 매핑 (확정 — 2026-04-28 사용자 결정)

| 웹소설 | 게임 챕터 | 비고 |
|---|---|---|
| 1화 | Ch.01 | 정부 선언 → 만찬 → 침실 눈물 |
| 2화 | Ch.02 | 아델린 야밤 → 붉은 보석 브로치 → 대공 가면 풀림 → 카이델 첫 등장 |
| 3화 | Ch.03 | 반역 모함 → 처형 |
| 4화 | Ch.04 | 회귀 → 거울 속 아델린 → 카이델 재회 |
| 5화~ | Ch.05~ (1:1 복귀) | 5화 = Ch.05(에르하), 6화 = Ch.06(렌) ... |

회귀를 4화에 도달. 게임 챕터당 웹소설 1화의 1:1 매핑. *호흡 보존 우선* — 게임 본문 풍성도가 높아 한 화 안에 한 챕터 이상 담는 것은 비현실적임을 1화 작성에서 검증.

**분량 현실** *(2026-04-28 1화 작업 학습)*: 게임 Ch.01 정사 라인 충실 반영 시 본문 약 5500~6000자 (§2 적정선 +60% 초과). 게임 본문 풍성도가 높은 챕터는 §2 한도가 비현실적일 수 있음 — *내용·후크 우선, 분량은 가변* 정책 채택. §2의 "약 3000자" 가이드는 *최소 호흡* 가이드이지 엄격 상한 아님으로 해석.

### 매핑 원칙
- `chapter_summary.md` 의 **사실관계**(누가 누구를 만났고 어떤 사건이 일어났는지)는 **변경 금지**
- 웹소설은 게임보다 *내면 묘사·미스터리 호흡*을 길게 가져갈 수 있음 — 단 §2 분량 한도 내
- 게임에 없던 디테일(시선·향기·내적 독백)은 자유롭게 보강 가능
- 웹소설 진행 중 새 설정·호칭이 생기면 `character_settings.md` 를 **먼저** 갱신 (SSOT 우선)

### 게임 선택지 분기 → 웹소설 정사 라인
웹소설은 단일 라인이므로 분기 중 *하나*를 정사로 채택. 채택 기준 (우선순위):
1. **가장 야릇·후크 강한 분기** (가속 매핑 의도와 정렬)
2. **호감도 점수 높은 분기** (+15·+10 등 — 보통 코인 분기)
3. **다음 회차 떡밥과 자연 연결되는 분기**

채택한 분기는 `회차요약.md` 에 반드시 명시.

### 충돌 해결 — 게임 JSON 본문 > chapter_summary > character_settings
충돌 시 게임 JSON 본문이 SSOT (가장 구체적). 예: 결혼 기간 = 게임 `chapter01.json` 본문 *삼 년* (`character_settings.md` "십 년"은 추후 정정 대상).

- [ ] **야릇 컷 미세 2~3 + 절정 1 패턴**으로 흩뿌려졌는가?
- [ ] **야릇 컷 손/팔 계열 비율 ≤ 40%**인가? (`회차요약.md` 부위 사용 기록과 누적 다양화 검증)
- [ ] 자조·서늘·미스터리 톤이 유지되었는가? *(자아도취 결의문이 들어가지 않았는가?)*
- [ ] 끝맺음이 다음 회 클릭을 유도하는 한 컷으로 닫혔는가?
- [ ] `chapter_summary.md` 사실관계와 모순되지 않는가?
- [ ] **em dash(`—`) 카운트 ≤ 5회**인가? (`grep -o "—" 파일 | wc -l`)
- [ ] 굵은체(`**`) 강조가 한 회차 3회 이내인가?
- [ ] `웹소설/회차요약.md` 에 이번 회차 1~2줄 요약 + 부위 사용 기록을 추가했는가?

## 11. 회차 요약 관리

새 회차 작성 직후 `웹소설/회차요약.md` 에 아래 형식으로 추가한다. 파일이 없으면 신규 생성.

```markdown
## {N}화. {부제}
- 주요 사건: {1~2줄}
- 등장: {캐릭터 나열}
- 다음 회 떡밥: {1줄}
- 매핑된 게임 챕터: Ch.{N} {필요 시 분기 채택 메모}
```

---

## 12. 파일 명명 규칙

- 본문: `{N}화_{한글_부제}.md` (예: `1화_공작가의_불청객.md`)
- 부제 안의 공백은 `_` 로 치환
- 회차 번호는 1자리·2자리 모두 가능 (`1화`, `12화`) — 0 패딩 금지

---

## 13. 작업 종료 보고 형식

회차 작성 완료 시 사용자에게 보고:
- 파일 경로
- 본문 글자수 (마크다운 제외 추정치) + `wc -m` 전체 길이
- 매핑된 게임 챕터
- 핵심 후크 한 줄
- `회차요약.md` 갱신 여부
